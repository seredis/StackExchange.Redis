Redis 8.12 is generally available, but the library API for its features is still marked experimental
while it settles, and may be subject to change.

New features in Redis 8.12:

- Bit enumeration (`BITRANGEINTARRAY`), surfaced as `IDatabase.StringBitPositions` / `StringBitPositionsAsync`:
  the positions of the set (or clear) bits in a byte or bit range of a string or native bitmap, with optional paging
- Per-member set expiration (`SADDEX`, `SEXPIRE`/`SPEXPIRE`/`SEXPIREAT`/`SPEXPIREAT`, `SPTTL`,
  `SPEXPIRETIME`, `SPERSIST`), surfaced as `IDatabase.SetAdd` (the `Expiration` overloads), `SetMemberExpire`,
  `SetMemberGetTimeToLive`, `SetMemberGetExpireDateTime` and `SetMemberPersist` (and async
  equivalents)
- Per-key eviction protection (`BLESS`), surfaced as `IDatabase.KeyBless`/`KeyUnbless`/`KeyBlessFlags` (and async
  equivalents) with the `BlessFlags` enum, and `IServer.BlessedKeys`/`BlessedKeysAsync` for enumeration
- Atomic sorted-set moves (`ZMOVE`, `ZMOVEMEMBER`), surfaced as `IDatabase.SortedSetMove` (from the
  low or high end), `SortedSetMoveByScore` (a score range) and `SortedSetMoveMembers` (named members, with an optional
  `When` condition on the destination), and async equivalents; each returns the moved entries, or `null` if nothing
  moved. The blocking `BZMOVE` is not exposed, as with every blocking command

The server API is now stable; the library API is not yet. Until this marker is retired, the shape of the
corresponding library features may still change, manifesting in either/both of build-time or run-time breaks.

While this seems *unlikely*, it must be considered a possibility. If you acknowledge this, you can suppress
this warning by adding the following to your `csproj` file:

```xml
<NoWarn>$(NoWarn);SER011</NoWarn>
```

or more granularly / locally in C#:

``` c#
#pragma warning disable SER011
```
